# Caves of Qud 한국어 번역 가이드

## 1. 세계관 요약

Caves of Qud는 **머나먼 미래의 사이언스 판타지** 세계를 배경으로 한 로그라이크 RPG다. 천년 단위 문명이 켜켜이 쌓인 세계에서 변이인, 순혈종, 지각 있는 식물, 로봇, 우주적 존재가 공존한다. "죽어가는 세계인가, 다시 태어나는 세계인가"라는 질문이 게임 전체를 관통한다.

핵심 분위기:
- 뉴웨이브 SF 문학의 시적이고 몽환적인 문체
- 고대와 초과학이 뒤섞인 퇴폐적 아름다움
- 건조하고 묵직한 유머
- 종교적·신화적 어조가 일상에 스며든 세계

## 2. 톤 앤 매너

### 2.1 기본 문체: 경어체 vs 반말

| 맥락 | 문체 | 예시 |
|------|------|------|
| **시스템 메시지·UI** | 합쇼체 (ㅂ니다/습니다) | "정착지에서만 체크포인트를 설정할 수 있습니다." |
| **아이템·오브젝트 설명** | 합쇼체 | "나무를 깎아 내려치기 좋은 몽우리 모양으로 만들었습니다." |
| **NPC 대화 (일반)** | 해요체 또는 합쇼체 | "흥미로워할 만한 소문이 하나 있습니다." |
| **NPC 대화 (격식)** | 하오체/합쇼체 혼용 | "방랑자여! 북쪽으로 모험을 떠나겠나?" |
| **NPC 대화 (거친/야생)** | 해체 (반말) | "침을 섞어볼까?" / "그거 하자." |
| **서적·로어 텍스트** | 문어체/고어체 | "옛적, 쿠드라는 땅이 살룸이라 불리던 시절에" |
| **능력·스킬 설명** | 합쇼체 | "당신은 자신의 팔다리 중 하나를 절단합니다." |
| **돌연변이 bearer 설명** | 명사구/~하는 자들 | "부신을 지배하는 자들" |

### 2.2 문체 원칙

1. **원문의 격조를 살린다.** Qud의 텍스트는 게임치고 문학적 수준이 높다. "flower-laden" 같은 표현을 "꽃이 있는"이 아니라 "꽃이 만발한"으로 옮기는 식으로, 원문의 격조에 걸맞은 한국어를 선택한다.

2. **과도한 의역을 피한다.** 세계관 고유의 표현(Water Ritual, Kasaphescence, Argent Fathers 등)이 전달하는 분위기를 해치지 않는다.

3. **간결함을 유지한다.** 게임 UI는 공간이 제한적이다. 아이템명, 스킬명, 메뉴 텍스트 등은 가능한 한 짧게 번역한다.

4. **플레이어를 "당신"으로 지칭한다.** 2인칭 "You"는 "당신"으로 통일한다.

## 3. 고유명사 처리 원칙

### 3.1 번역하는 것

| 유형 | 원칙 | 예시 |
|------|------|------|
| 일반명사적 이름 | 의미를 살려 번역 | Long Sword → 장검, raw bear meat → 생 곰고기 |
| 지형·장소 (일반) | 의미 번역 | desert canyons → 사막 협곡 |
| 시간 표현 | 의미+분위기 번역 | Beetle Moon Zenith → 딱정벌레 달 정점, Jeweled Dusk → 보석빛 황혼 |
| 돌연변이 카테고리 | 의미 번역 | Physical Mutations → 신체 변이, Morphotypes → 형태형질 |
| 직업·역할명 | 의미 번역 | miner → 채굴꾼, turret tinker → 터렛 땜장이 |

### 3.2 음차하는 것

| 유형 | 원칙 | 예시 |
|------|------|------|
| 인명 | 한글 음차 | Argyve → 아르자이브, Barathrum → 바라스룸 |
| 고유 지명 | 한글 음차 | Joppa → 조파, Bethesda Susa → 베데스다 수사 |
| 종족명 (고유) | 한글 음차 | Dromad → 드로마드 |
| 달력 이름 | 한글 음차 | Nivvun Ut → 니븐 우트, Tishru → 티슈루 |

### 3.3 원문을 유지하는 것

| 유형 | 원칙 | 예시 |
|------|------|------|
| 템플릿 변수 | 절대 번역하지 않음 | `=name=`, `=pronouns.siblingTerm=`, `=player.t=` |
| 종교·문화 고유 용어 | 원문 유지 또는 음차 | Argent Fathers, Shekhinah, Kasaphescence |
| 색상 코드 | 구조 보존 | `{{W|텍스트}}`, `{{G|텍스트}}` |
| 기술적 ID | 번역하지 않음 | Name 속성 (XML ID로 사용되는 경우) |

### 3.4 혼합 표기 (음차 + 의미)

독자가 의미를 파악하기 어려운 고유명사는 첫 등장 시 혼합 표기를 고려한다:
- Six Day Stilt → Six Day Stilt (문맥상 장소임이 명확하므로 원문 유지)
- Water Ritual → 물의 의식
- True Kin → 순혈종
- Consortium of Phyta → 식물 연합

## 4. 기술적 규칙

### 4.1 절대 건드리지 않는 것

```
=name=                          # 템플릿 변수
=subject.waterRitualLiquid=     # 템플릿 변수
=pronouns.siblingTerm=          # 대명사 변수
=player.reflexive=              # 플레이어 변수
=verb:grab=                     # 동사 변수
{{W|텍스트}}                     # 색상 코드 (구조만 보존, 내부 텍스트는 번역)
{{emote|동작}}                   # 이모트 (내부 텍스트는 번역)
~CmdMoveN                       # 키바인딩 참조
{{?KB|...}}                     # 키보드 바인딩
{{?Gamepad|...}}                # 게임패드 바인딩
<spice.xxx.!random>             # HistorySpice 참조
<entity.name>                   # 엔티티 참조
*var*                           # 플레이스홀더
[[A.]]                          # 선택지 마커 (Books)
```

### 4.2 색상 코드 내부 번역

색상 코드의 **구조**는 보존하되, **내부 텍스트**는 번역한다:
- `{{G|Physical Mutations}}` → `{{G|신체 변이}}`
- `{{W|Song of the Sky-Bear}}` → `{{W|하늘곰의 노래}}`
- `{{r|raw bear meat}}` → `{{r|생 곰고기}}`

### 4.3 물결표(~) 구분자

대화 선택지에서 `~`는 랜덤 선택지 구분자다. 구조를 그대로 유지한다:
```
침을 섞어볼까?~
그거 하자.~
{{emote|입술을 핥는다}}~
내 목마름은 내 것이고, 네 물은 네 것이다.
```

### 4.4 조사 처리

한국어 조사는 앞 글자의 받침에 따라 달라진다. 템플릿 변수 뒤에는 `을(를)`, `이(가)`, `은(는)` 형태로 양쪽을 병기한다:
- `=name=을(를) 발견했습니다!`
- `{0}의 위치를 발견했습니다.`

## 5. 카테고리별 번역 지침

### 5.1 대화 (Conversations, HiddenConversations)

- NPC의 **성격과 지위**에 맞는 어조를 유지한다.
  - 조파 농부: 격식 있지만 따뜻한 하오체 ("방랑자여! 북쪽으로 모험을 떠나겠나?")
  - 상인: 비즈니스적 합쇼체 ("거래합시다.")
  - 야생 변이체: 거친 반말 ("침을 섞어볼까?")
- 물의 의식(Water Ritual) 관련 문구는 **의례적이고 장중한 어조**를 유지한다.
- 선택지(choice) 텍스트는 플레이어의 말이므로, NPC에게 합쇼체를 사용한다.

### 5.2 서적 (Books)

- 게임 내 서적은 **문학 작품**이다. 시, 역사서, 전설 등 장르에 맞는 문체를 사용한다.
- 고어체/문어체를 적극 활용한다 ("옛적", "이름하여", "있었나니").
- 줄바꿈과 문단 구조를 원문과 동일하게 유지한다.

### 5.3 아이템·오브젝트 (ObjectBlueprints)

- **DisplayName**: 가능한 한 짧고 명확하게. 색상 코드 보존.
- **Description Short**: 합쇼체로 서술. 아이템의 물리적 특성과 분위기를 전달.
- **Food Message**: 음식 먹을 때 나오는 메시지. 합쇼체.
- 대괄호 `[벽]`, `[생고기]` 등의 형식은 원문 그대로 유지.

### 5.4 스킬·돌연변이 (Skills, Mutations)

- 스킬/돌연변이 **Description**은 능력의 효과를 정확하게 전달하는 것이 최우선.
- 수치와 비율은 원문 그대로 유지 ("75% 확률로", "두 배로").
- `BearerDescription`은 "~하는 자들" 형식의 명사구로 번역.

### 5.5 퀘스트 (Quests)

- 퀘스트 제목은 간결한 명사구.
- 퀘스트 단계(step) 텍스트는 해요체로 지시 ("~하세요", "~로 이동하세요").
- Accomplishment, Hagiograph, Gospel은 서사적 문체.

### 5.6 옵션·커맨드 (Options, Commands)

- UI 텍스트이므로 최대한 간결하게.
- Commands는 동사 원형 또는 명사구 ("북쪽으로 이동", "인벤토리 열기").

### 5.7 HistorySpice

- 절차적으로 생성되는 텍스트이므로, 조각이 조합되었을 때 자연스러운 문장이 되도록 번역.
- `<spice.xxx>`, `<entity.name>` 등의 참조를 반드시 보존.
- 문장 조각이므로 끝맺음 없이 번역해도 되는 경우가 많다.

### 5.8 Naming

- 단순 번역 불가. 한국어 이름 생성 체계를 별도 설계해야 한다.
- 현재 inject 미지원이므로, 별도 작업으로 분류.

### 5.9 Genders

- 한국어에는 he/she/they 구분이 약하므로, 게임 내 문맥을 고려하여 재설계 필요.
- 대명사 속성(Subjective, Objective 등)이 템플릿 변수로 사용되므로 신중하게 접근.

## 7. 품질 체크리스트

번역 후 다음을 확인한다:

- [ ] 템플릿 변수(`=...=`)가 손상되지 않았는가?
- [ ] 색상 코드(`{{X|...}}`)의 구조가 보존되었는가?
- [ ] 물결표(`~`) 구분자가 유지되었는가?
- [ ] 조사(을/를, 이/가, 은/는)가 올바른가? 변수 뒤에는 병기 형태인가?
- [ ] NPC의 어조가 캐릭터에 맞는가?
- [ ] 고유명사의 표기가 용어집과 일치하는가?
- [ ] 줄바꿈과 공백이 원문과 동일한가?
- [ ] 번역 누락 없이 모든 텍스트가 옮겨졌는가?
- [ ] UI/메뉴 텍스트가 공간에 맞게 간결한가?
